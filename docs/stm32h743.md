# STM32H743 boards: design notes and measurements

DEV190806042, FK743M5-XIH6, STM32H7_CORE V1.0 / V1.3 on MicroPython 1.29.0 with the
PyDevices LVGL binding (LVGL 9.5). The old port and its sources are described in
`docs/stm32-inventory.md`. Work in progress: filled in phase by phase.

## Build

- Out-of-tree boards in `boards/stm32/<BOARD>/` (`BOARD_DIR`), STM32H7_CORE with
  `BOARD_VARIANT=V10|V13` (required). `scripts/build.sh stm32 <BOARD> [VARIANT]`.
- `manifest.py`: LVGL (`$(LVMP_DIR)/manifest.py`) and `modules/st_ltdc`;
  `manifest_nolvgl.py`: `modules/st_ltdc` only (bring-up). With
  `FROZEN_MANIFEST=.../manifest_nolvgl.py` the build goes to `build-<NAME>-nolvgl` and
  `dist/<NAME>-nolvgl-*`.
- **Floats:** Python floats stay `double` (`MICROPY_FLOAT_IMPL = double`, as in the old
  port; the H743 FPU is double precision). The port then links only MicroPython's
  double libm, while LVGL 9.5 calls `sinf`, `cosf`, `atan2f`, `sqrtf`
  (`lv_arclabel.c`, `lv_indev_gesture.c`): undefined at link time. Fixed on the
  board side, no patch: `boards/stm32/lvgl_libm.mk` adds the single-precision files
  of `lib/libm` that provide them.
- **Soft reset:** `MICROPY_BOARD_END_SOFT_RESET` = `st_ltdc_board_end_soft_reset()`
  (`modules/st_ltdc/st_ltdc.c`): `mp_lv_deinit_gc()` when LVGL is built in, then the
  port's own `boardctrl_end_soft_reset()`. Test: `tests/hil/stm32/t02_lvgl_softreset.py`.
- **Size:** about 1.12 MB of the 2 MB internal flash, 945–953 KiB free (table in
  `docs/stm32-inventory.md`).

## Display driver (`modules/st_ltdc`)

API (module `st_ltdc`, aligned with `rgbpanel` of the RP2350): `init(width, height,
hsync, hbp, hfp, vsync, vbp, vfp, *, polarity=0, pclk_hz=50_000_000, buffers=2,
backlight=100)`, `deinit()`, `framebuffer(i=0)`, `shown()`, `swap(timeout_ms=100)`,
`backlight([pct])`, `frame_count()`, `underruns()`, `wait_vsync(timeout_ms=100)`,
`info()`, and with LVGL `lv_display_create(partial_lines=0)`, `lv_tick_install()`.
Panel timings: `python/panels.py` (`st_ltdc.init(**panels.get("IPS1024x600"))`).

Choices:

- **Framebuffers outside the GC heap** (option b of the plan): the top
  `MICROPY_HW_LTDC_FB_BYTES` = 4 MB of the SDRAM (0xC1C00000-0xC1FFFFFF), the heap
  ends below it (`MICROPY_HEAP_END`, 28 MB of heap). Room for two 1024x600 RGB565
  buffers (2 x 1 228 800 B) and the PARTIAL render buffers. Never freed: the LTDC
  keeps scanning valid memory across a soft reset and the image stays (as on the
  RP2350); no root pointers, nothing to rescue in the soft-reset hook. The old driver
  used `m_malloc` on the heap, which a soft reset frees while the LTDC still reads it.
- **Write-through MPU region on exactly that zone, region 15.** Not region 6 as in the
  old driver: since 1.29 `dma.c` (`dma_protect_rx_region`, SD card reads) reprograms
  and then *disables* regions 6 and 7, which would silently turn the framebuffers back
  to write-back after the first SD read. The zone is 4 MB aligned, as the MPU needs.
- **Registers programmed directly** (LTDC, DMA2D; PLL3 through
  `HAL_RCCEx_PeriphCLKConfig`): no HAL LTDC/DMA2D sources, no `hal_conf` changes, no
  `HAL_LTDC_MspInit` per board. Pins are data in each `mpconfigboard.h`
  (`MICROPY_HW_LTDC_PINS`), checked against `boards/stm32h743_af.csv` and against the
  other pins of each board.
- **Pixel clock at run time**: PLL3 M=5 (5 MHz reference), N and R searched for the
  closest output, VCO 192-836 MHz. 50 MHz gives N=40, R=4, the old fixed setting.
- **Swap without an ISR doing LVGL work**: the flush writes the new layer address and
  asks for a reload at vertical blanking, then polls until the LTDC has taken it
  (at most one frame); `lv_display_flush_ready()` is called from the flush itself. The
  only interrupt counts frames (line interrupt after the active area), FIFO underruns
  and transfer errors.
- **PARTIAL mode**: render buffers in the zone (write-through, so the DMA2D reads what
  the CPU wrote), each area copied by the DMA2D into the shown buffer, synchronously.
- **AXI QoS** as in the old driver (SDRAM target 1 outstanding transaction, LTDC and
  DMA2D before the CPU). Its cost for the CPU (heap in SDRAM) to measure in phase 5.
- **Backlight**: GPIO on/off (`MICROPY_HW_LTDC_BL`, active high as in the old driver,
  `MICROPY_HW_LTDC_BL_ACTIVE`); PWM after the polarity is confirmed by eye.
- **RGB565 only** (LVGL's colour depth in the PyDevices `lv_conf.h` is 16).

Tests: `tests/hil/stm32/t03_panel.py` (patterns A-D, frame rate, underruns, flash
write), `tests/hil/stm32/flash_stress.py`, `tests/hil/stm32/t03_softreset.py`. The
Python side of the first two was run on the unix port with a stand-in `st_ltdc`
(pattern pixels checked: corners, bar colours, 32/64 ramp steps); not yet on hardware.
